# 通用前端质量规范 — 融合「前端开发规范 / 代码简化 / 前端UI工程 / 前端设计」

> 通用最佳实践，叠加在本项目专属规范之上（project-conventions.md 优先）。

## 1. 代码简化五原则（code-simplification）

1. **保行为**：不改变任何输入/输出/副作用/错误行为；不确定是否等价就不简化
2. **随约定**：简化 = 更符合项目惯例，而非强加外部风格；先读项目规范再动手
3. **重清晰**：显式优于巧妙；嵌套三元/链式 reduce 换成 if/else 或具名函数
4. **守平衡**：不过度简化——保留有价值命名的抽象；不只为行数而简化
5. **限范围**：只简化本次改动相关代码，不做顺手牵羊的重构

**简化信号表**：

| 模式 | 信号 | 简化 |
| --- | --- | --- |
| 深嵌套（3+ 层） | 控制流难跟 | 卫语句 / 提取函数 |
| 长函数（50+ 行） | 多职责 | 拆成具名函数 |
| 嵌套三元 | 需脑内压栈 | if/else 链 / switch / 查表对象 |
| 布尔参数旗标 | `doThing(true, false, true)` | options 对象 / 拆函数 |
| 重复条件 | 多处同一 if | 提取谓词函数 |
| 泛名变量 | `data/result/temp/item` | 具名描述：`userProfile` |
| 注释解释 what | `// increment counter` | 删注释，代码自明 |
| 注释解释 why | `// Retry because API flaky` | 保留（代码表达不了意图） |
| 重复逻辑（5+ 行多处） | 复制粘贴 | 提取共享函数 |
| 死代码 | 不可达分支/未用变量/注释块 | 确认后删除 |
| 冗余断言 | 强转已推断类型 | 移除 |

**红色信号**：需要改测试才能过（说明改了行为）；简化后更难懂；删了错误处理；简化不理解的代码；批量大改一次提交。

### 1.1 简化四步流程（code-simplification 流程）

1. **理解再动手（Chesterton's Fence）**：改/删任何东西前先搞清它为什么存在——谁调用、边界、错误路径、是否有测试定义行为、是否历史/性能约束。看不懂就先读更多上下文，不要动。
2. **识别信号**：对照上方「简化信号表」逐条扫（深嵌套/长函数/嵌套三元/泛名/重复/死代码…），只挑真问题，不做无谓简化。
3. **增量应用**：一次只做一个简化，每步后可独立验证（本项目不跑构建，靠静态自查 + 用户本地 `npm run dev` 验证）。**简化与功能/修复改动分开提交**，避免混在一起无法回滚。
4. **验证回看**：对比前后——是否真的更易读？是否引入与项目不一致的新模式？diff 是否干净？队友是否会认可。若「简化版」反而更难懂，回退。

> **Rule of 500**：重构若触及 500+ 行，优先写 codemod/脚本批量处理，而非手工逐个改。

### 1.2 语言示例（TypeScript / JavaScript）

```typescript
// 删冗余 async 包裹
async function getUser(id: string): Promise<User> { return await userService.findById(id) }
// →
function getUser(id: string): Promise<User> { return userService.findById(id) }

// 冗长条件赋值 → 短路
let name: string
if (user.nickname) name = user.nickname
else name = user.fullName
// →
const name = user.nickname || user.fullName

// 手动数组构建 → 声明式
const active = users.filter((u) => u.isActive)

// 冗余布尔返回
function isValid(s: string): boolean { if (s.length > 0 && s.length < 100) return true; return false }
// →
function isValid(s: string): boolean { return s.length > 0 && s.length < 100 }
```

> 简化 ≠ 删逻辑：保行为优先；不删错误处理、不删为了可读性的具名抽象、不跨当前任务范围顺手重构。

## 2. TypeScript 规范

- 必须定义接口/类型；禁止 `any`，能用 `unknown` 替代
- 函数参数与返回值必须标注类型；类型复用用 `type` / `interface`
- 变量 `const` 优先；异步 `async/await`；禁魔法数字抽为常量
- 数组优先 `map/filter/reduce`

## 3. Vue 组件规范

- 组件名多单词，避免与 HTML 重名
- props 必须定义类型、默认值、校验
- 计算属性避免副作用；watch 慎用，优先 computed
- 方法命名动词+名词；指令缩写 `:` `@` `#`

## 4. UI 工程规范（前端UI工程 + impeccable 融合）

### 4.1 设计上下文先行

开始 UI 工作前先明确：目标用户、使用场景、品牌调性（本项目 = 暗色 GIS 大屏、科技青强调、金色点缀、数据可视化密集）。

### 4.2 规避「AI 审美」

| ✅ 做 | ❌ 不做 |
| --- | --- |
| 项目真实调色板（--color-* 变量） | 紫/靛蓝铺满、默认青+深色发光 |
| 一致圆角/间距刻度 | 圆角拉满、到处超大 padding |
| 内容优先布局、真实文案 | 模板式 hero、Lorem 占位文案 |
| 合理阴影 | 层层阴影、毛玻璃滥用 |
| 有意图的动效（指数缓动） | 动画化布局属性、回弹弹性 |

### 4.3 状态管理选型（选最简单够用的）

```
本地 ref/reactive        → 组件内 UI 状态
提升状态                 → 2-3 个兄弟组件共享
provide/inject           → 主题/地图实例等读多写少
URL 状态(query)          → 过滤/分页/可分享状态
全局 store               → 全应用共享的复杂客户端状态
```

prop drilling 别超过 3 层。本项目惯例：地图实例 `mapIns` 用 ref + provide/inject；图层勾选状态页面层 reactive 集中管理。

### 4.4 可访问性（WCAG 2.1 AA，按需）

- 交互元素可键盘访问（优先原生 `<button>`）
- 无可见文字的交互元素加 `aria-label`
- 空态/错误态/加载态都要有意义（不空白屏）
- 对比度：正文 4.5:1、大字 3:1；不只靠颜色传信息（配图标/文字）

### 4.5 响应式

- 移动优先；断点测 320 / 768 / 1024 / 1440px
- 本项目大屏为主，但面板在小屏需折叠/换行（参照既有 `@media (max-width: 767px)` 处理）

### 4.6 加载与过渡

- 内容用骨架屏（非 spinner）
- 项目风格：暗色 + 青色细滚动条 + 面板渐变卡片，所有视觉与 mapcardNew 保持一致

### 4.7 Impeccable 设计速查（高品质 UI，避免泛 AI 审美）

#### AI Slop Test
> 把界面给别人看并说「这是 AI 做的」，对方会立刻信吗？会 → 就是问题。独特界面应让人问「这怎么做的」，而非「哪个 AI 做的」。

#### DO / DON'T 速查（本项目暗色 GIS 大屏适配）

| 维度 | ✅ DO（项目做法） | ❌ DON'T（泛 AI 审美） |
| --- | --- | --- |
| 字体 | 项目字体栈 + 模块化字号/字重层级；数值用等宽感数字体 | Inter/Roboto 当万能；标题上方堆大图标 + 圆角 |
| 色彩 | `var(--color-*)` 项目调色板（深蓝底 + 科技青 + 金边）；状态/对象语义色 | 纯黑 `#000`/纯白 `#fff`；青+深色发光、紫蓝渐变、霓虹点缀 |
| 空间 | 变化间距制造节奏；面板内 `padding` 克制；内容优先 | 万物皆卡片 / 卡片套卡片；英雄指标模板；一切居中 |
| 动效 | 状态变化的指数缓动（ease-out-quart / expo） | 动画化布局属性；回弹 / 弹性缓动 |
| 交互 | 渐进式披露；有意义的空态/加载/错误态 | 重复信息；所有按钮都设为主要按钮 |
| 响应 | 容器/断点自适应，小屏折叠面板不隐藏关键功能 | 移动端隐藏关键功能 |
| 文案 | 每词有存在价值，用真实业务文案 | 重复用户已可见信息、Lorem 占位 |
| 细节 | 有意图的装饰强化品牌（四角青饰 / 标题栏背景图） | 毛玻璃滥用；圆角 + 通用阴影；无意义火花线 |

#### 场景化导航（识别到需求时按需深化）
- **视觉/冲击力**：界面平淡缺个性 → 强化项目美学观点（更大胆的语义色对比 / 更克制的留白），不堆特效
- **布局/排版**：布局不对、间距不一致、层次弱 → 对齐项目基线（左右 320/340px、`mapcardNew` 面板、12px 呼吸间隙）
- **动效/体验**：需动画/微交互/空状态引导 → 指数缓动 + 有意义的空态
- **质量保障**：a11y / 性能 / 响应式 / 反模式审查 → 对照本文件第 4~6 节逐条自检
- **设计系统化**：提取组件/token/复用模式，收敛到 `mapcardNew` + `color-common.less` 变量体系

> 每次设计都应不同、有意图；但**本项目有统一暗色大屏基调**，所有页面必须收敛到 `--color-*` 与 `mapcardNew` 风格，不各搞一套。

## 5. 性能规范

- 图片压缩/WebP/懒加载；路由懒加载（`() => import(...)`）
- 防抖节流高频事件（地图移动、输入、resize）
- 大数据列表虚拟滚动 / 分页
- 减少冗余渲染（v-if/v-show 取舍、computed 缓存）
- ECharts 必须 ResizeObserver 监听容器（不能只靠 window.resize）

## 6. 安全规范

- 防 XSS：过滤用户输入、插值用 `{{ }}` 不拼 HTML
- 防 CSRF：token 校验（本项目 axios 已自动带 token）
- 敏感信息不存 localStorage（仅 ACCESS_TOKEN）
- 接口权限控制后端兜底；前端不硬编码密钥/Token

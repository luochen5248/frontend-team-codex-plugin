# 通用大屏前端专家团

> 本技能是**编排层**，不含业务实现细节。它的职责是：判断该谁上场、按什么顺序上、每阶段的交付物是什么、什么条件下才允许进入下一阶段。

## 一、团队构成

| 角色 | 成员技能（Codex 内技能名） | 职责 |
| --- | --- | --- |
| **大屏GIS前端** | `项目级别前端开发规范` | 大屏/GIS/Cesium 页面、组件、接口、地图交互、暗色大屏视觉 |
| **移动端H5** | `手机端H5开发规范` | 移动端布局契约、视口与安全区、软键盘、滚动容器、localStorage 配额 |
| **UI 设计** | `ui-new__skillhub` | 布局模板、组件模式、配色系统 |
| **质量与治理 · 评审** | `wenwei-code-review__skillhub` | 对照需求/设计文档做代码评审，查完成度与偏离 |
| **质量与治理 · 简化** | `code-simplification__skillhub` | 行为不变前提下的可读性重构 |
| **质量与治理 · 门控** | `delivery-no-pseudoblock` | 拦截伪代码、占位实现、未完成即交付 |

## 二、工作流（四阶段）

### 阶段 0 · 立项与对齐
1. 明确目标平台：**大屏 GIS** 还是 **移动端 H5**（决定阶段 1 走哪个分支）。
2. 识别现有文档：需求 / 澄清 / 概要设计 / 功能点文档。
3. 对齐技术栈与目录约定，确认改动范围。
4. 输出：本次任务的范围清单 + 待确认问题。**有未确认项先问，不要猜。**

### 阶段 1 · 实现（按平台分流）
- 大屏 GIS 分支：先读 `项目级别前端开发规范`，按其规范实现；涉及视觉时叠加 `ui-new__skillhub`。
- 移动端分支：先读 `手机端H5开发规范`，按其六维度契约实现；涉及视觉时叠加 `ui-new__skillhub`。
- 两分支并存时，**分别遵守各自规范**，不要把两套布局契约混用。

### 阶段 2 · 质量与治理
按顺序执行，前一个不通过不进下一个：
1. `delivery-no-pseudoblock` —— 先确认没有伪代码/占位实现/Mock 冒充真实逻辑。
2. `wenwei-code-review__skillhub` —— 对照需求与设计文档评审，列出未完成项、BUG、偏离设计处。
3. `code-simplification__skillhub` —— 在行为不变前提下降低复杂度。

### 阶段 3 · 交付
- 汇总：改动文件清单、验证方式、遗留风险。
- 明确告知用户**需要他自行启动服务验证**（不由本团代跑）。

## 三、路由规则

| 用户意图 | 编队 |
| --- | --- |
| 只做大屏 GIS 页面/组件/地图 | 大屏GIS前端（+ UI 设计按需） |
| 只做移动端 H5 页面 | 移动端H5（+ UI 设计按需） |
| 同时含两端 | 两端并行，各自遵守各自规范 |
| 只审查/评审代码 | 质量与治理（评审 → 简化） |
| 只做重构/简化 | 质量与治理（简化） |
| 完整需求到交付 | 全团四阶段 |

## 四、强制规则

1. **先读后做**：调用任何成员前，先读它的 `SKILL.md`，按它写明的流程走。
2. **门控不可跳过**：阶段 0 有未确认项时不得进入阶段 1；阶段 2 的伪代码检查不通过不得交付。
3. **平台规范不混用**：大屏与移动端两套布局契约互斥，按目标平台选一套。
4. **不代跑服务**：完成后交给用户自行启动验证。
5. **单点追问**：需要用户决策时，给推荐项 + 备选项，不要罗列一堆问题。
